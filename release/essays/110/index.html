Vibe coding for estrategIA readers: from a prompt to a simple application with Google AI Studio

A November 2025 demonstration of building and refining a press-release-generator prototype through conversation, with the complete visible prompts and outputs.

Fernando Nieto LobatoAuthor
5 November 2025Originally published in Spanish
16 min readEnglish edition · 29 September 2026

Archive context: this tutorial and its product-access instructions date from 5 November 2025. The prompts, fictional council example and model responses below reproduce the author's historical experiment, not current instructions from this edition. The quotation attributed to Karpathy is translated from the Spanish source; its original English wording was not independently checked. The English release visible in the third screenshot is transcribed directly, retaining its original spelling.

What if you could create a working application in a few minutes without knowing how to program, using words alone? That is exactly what vibe coding promises: a phenomenon that, thanks to AI, is radically transforming who can build technology, and one I had long wanted to introduce to you in estrategIA, even at the most basic level.

The term vibe coding was coined in February this year, 2025, by Andrej Karpathy, former director of AI at Tesla and former OpenAI researcher, to describe a new paradigm: creating software by talking to an artificial intelligence, without writing a single line of code.

Its usefulness for the general public is immense because it removes the technical barrier that has traditionally separated ideas from execution. You no longer need to be a programmer to create simple digital tools. As this technology matures—it is still early, although, as you will see in this article, basic things can already be done easily—it will allow experts in any field to build prototypes and bespoke solutions to their specific problems incredibly quickly. At the very least, they will be able to make a prototype that can later be scaled with a team and relatively low costs compared with the traditional model.

The concept is revolutionarily simple. Open a tool such as Google AI Studio, which launched its new interface for building applications without code this October, free of charge, and tell it what you want. For example, this is the one we created: “I want a system that writes press releases from a set of data I provide in a form, also translates the release into English, and offers texts for sharing it on social media.” The AI generates all the necessary code. If something does not work as expected, you do not need to understand what went wrong in technical terms: you simply describe the problem or the change you want, and the AI adjusts it. It is a completely conversational, iterative process that almost always works satisfactorily for simple tasks.

The magic is made possible by large AI language models trained on billions of lines of existing code. These systems can translate our human intention, expressed in natural language, directly into working applications. As Karpathy said: “The most popular programming language now is English”—or Spanish, in our context. The historic barrier between “person with an idea” and “working application” is beginning to disappear, although for now that remains a long way off in complex or large projects.

Why does this matter for citizens, consultants and public servants? Because it will democratise capabilities that previously cost tens of thousands of dollars and months of development. A simple chatbot for citizen services, a tracker of local bills or a press-release generator: tools that once required hiring entire development teams are now beginning to be created in hours or a few days on very small budgets. The technology is still in its infancy, but it is progressing very rapidly. At least the prototype is very easy to make, allowing tests to be run or making it clear exactly what to ask of the technical team building the final solution. For politics and government, especially in countries, regions or towns with fewer resources, this means that small teams, grassroots organisations and public offices will finally be able to carry out coding projects easily—if this takes hold as it seems likely to, and we see progress in software comparable to that in text, images or video.

There is, however, an important caveat: the technology's present state still clearly argues against projects involving sensitive citizen data, government financial systems, critical infrastructure or anything requiring strict regulatory compliance. We therefore advise experimenting and developing small projects in other areas without that particular difficulty, bearing firmly in mind that this is still a nascent technology.

A simple press-release application¶

But since we are convinced that the best way to teach you about vibe coding is to show it to you, here is an example generated in Google's AI Studio. We believe this is currently the simplest free platform for developing these applications, or at least prototyping them. It then allows you to save the application in GitHub or even deploy it fairly easily in Google's own cloud, though that does involve some API costs.

The simple example application we have created to show you is a press-release generator based on a form, with a few extras.

WE ENCOURAGE YOU TO TAKE A LOOK HERE

(Note: we have shared it openly, but it is not in production. To view it, you will need a Google account and will be asked to grant a series of permissions. Anyone can view the application and, if they make a copy—which we recommend—save it for personal use and request changes. For example, a colleague and friend to whom we sent the test a few days ago generated an identical version in Portuguese almost instantly.)

With just that idea in mind, as described above, we asked GPT-5 Thinking to help us create a prompt to use in AI Studio. The next image shows the main part of what it returned:

Screenshot 1: translated historical prompt.

2) Initial prompt to generate the MVP—paste it exactly as it is

Master prompt, block 1: “Describe the app”

I want you to generate a simple, ready-to-use web application that takes inputs from a form and produces:

  1. A press release in Spanish in journalistic format: location and date at the top, headline, subheading, a 35–50-word lead, a body of 3–5 paragraphs with quotations, boilerplate and contact information.
  2. An English version faithful to the original.
  3. Five alternative headlines.
  4. Three coordinated posts for X/LinkedIn/Instagram, of 280/300/150–220 characters respectively.

Requested interface:

  • Required fields: topic/provisional title; key facts as a list; verbatim quotation and spokesperson/role; call to action; contact information; tone—urgent, celebratory or informative; scope/locality; release date.
  • Controls: ES/EN selector, default ES; “generate social posts” checkbox; Generate button; and Preview panel with Copy and Download .md buttons.
  • Validation: prevent output if key facts or contact information are missing; warn if the quotation lacks quotation marks.

Editorial rules:

  • Do not invent data or quotations. If something is missing, show it in square brackets: [PENDING].
  • Maintain institutional neutrality; avoid unsupported adjectives.
  • Adapt the style to the local context: clarity and public usefulness.
  • In Spanish, use EFE/RAE conventions: capital letters for proper names, and a dateline such as “Salamanca, 31 October 2025”.
  • In English, use an approximation of AP Style.

Output deliverables in the preview:

  • Markdown with clear headings and separators made of three hyphens.
  • A “Review checklist” block covering data, quotations, permissions and links.
  • A Metadata field containing word count and estimated reading time.

Implement everything with a clean, single-panel UI, show readable error messages, and prepare Copy and Download .md functions.

Refining the application through conversation¶

Finally, having checked that the application worked, we suggested improving the design and applying, for example, Institución Educativa ALEPH's corporate red. Making changes is very simple: just ask the model in text. Since the example was intended for estrategIA readers, we also asked it to adapt the sample text explaining the fields to a council or government communications example.

2. Improved form structure: To make the form less overwhelming, I have grouped the fields into logical sections—“Essential information”, “Content and spokesperson”, “Final details”—using clear borders and legends, which guide the user more intuitively.

3. Polished design: I have adjusted spacing, borders and shadows to give the panels a more professional, refined appearance. Buttons and form fields now match the new visual identity.

4. Attractive preview: The preview panel now has a more visual initial state, with an icon and a welcome message inviting action.

5. Performance optimisation: I have changed the AI model to gemini-2.5-flash, which offers an excellent balance between quality and speed, so that you get results faster.

The application could now be exported in various ways or deployed directly in Google's cloud. If anyone wants to change something, it is as simple as making a copy from the menu at the top right of the screen and then asking for changes to the application.

This is only a simple example. More powerful vibe coding tools are already on the market, and the sector has developed enormously in a very short time. Within a few months or a few years, it will probably become possible to tackle, with the same ease, more complex projects requiring servers, databases and so on. We invite you to try generating your own simple applications. If you need ideas, go straight to this week's GPT-5 prompt section, where we have left a prompt that will generate several ideas for you to try.
